# Decision log

Every modelling choice, why it was made, and its source. This becomes the methodology chapter.
Status: **Fixed** (sourced) · **Assumption** (needs justifying in the thesis) · **Verify** (check before final results) · **Open** (decision pending).
All values live in `config/`; changing one never needs a code change.

| ID | Decision | Why | Source | Status |
|----|----------|-----|--------|--------|
| D-001 | All parameters in `config/default.yaml` + `config/params/`; scenarios override only what differs; each run saves `config_used.yaml` | Reproducibility; every figure traceable to its settings | — | Fixed |
| D-002 | Hourly time step, one calendar year, local time (Asia/Dubai, UTC+4, no DST); timestamps mark the **start** of each hour; sun position taken at hh:30 | Matches tariff and data resolution; avoids half-hour solar offset errors | — | Fixed |
| D-003 | PV: pvlib chain — Hay-Davies transposition, Faiman cell temperature, PVWatts DC + losses + PVWatts inverter. 32 kWp shared array, 25° tilt, south-facing, 5 % soiling | Standard, citable open-source chain. Soiling above pvlib default because of desert dust | pvlib (Holmgren et al., 2018); array size assumed | Assumption (array size, soiling) |
| D-004 | Household demand is synthetic: base + appliance shape + temperature-driven cooling, rescaled to each home's annual kWh and cooling share; four occupancy archetypes; UAE weekend Sat–Sun | No public hourly UAE villa data found yet. Cooling-dominated profile mirrors Dubai reality | Annual kWh (22–46 MWh) and cooling share (65–70 %) assumed | **Assumption — find published UAE villa consumption figures to justify** |
| D-005 | Battery: Powerwall 2 (NMC) default, Powerwall 3 (LFP) scenario; 3 units (40.5 kWh); round-trip efficiency split symmetrically (√RTE each way); both modelled as AC-coupled | Datasheet values; chemistry matches the Schmalstieg (NMC) and Naumann (LFP) ageing papers. PW3 is really DC-coupled to PV — AC-coupled simplification slightly understates PW3 efficiency | Tesla PW2 AC datasheet (AU/NZ); Tesla PW3 datasheet 2024 | Fixed (specs); Assumption (3 units, AC coupling); Verify (PW3 RTE 89 %) |
| D-006 | Tariff: DEWA residential slabs (23/28/32/38 fils per kWh, monthly blocks) + 6 fils fuel surcharge + 5 % VAT, billed **per home** | Real tariff; each villa keeps its own DEWA account | DEWA "Slab Tariff" page | Fixed; Verify fuel surcharge (changes monthly) |
| D-006a | Export treatment is a parameter: `net_metering` (Shams Dubai — exported kWh offset imported kWh at own slab rate, surplus carried forward, no cash) / `no_credit` / `feed_in` | **Key finding:** under monthly kWh net metering the grid acts as a free, lossless battery, so a physical battery *cannot* lower the bill — it only adds round-trip losses. Pipeline test confirms Brain A costs slightly more than PV-only under net metering. A shared array serving four separate plots may also not qualify for Shams Dubai, which is plot-based | Shams Dubai net-metering rules | **Open — choose headline case** |
| D-006b | Hypothetical TOU tariff (off-peak 00–07, shoulder, peak 16–22) scaled to be revenue-neutral against DEWA slabs for the default homes | Tests whether the price *shape* makes smart control worthwhile, without changing the price *level* | Own design, clearly labelled hypothetical | Assumption |
| D-007 | Weather year: 2023 (default) | NASA POWER and PVGIS both cover 2023 | — | **Open — realistic day-ahead forecasts (Open-Meteo Previous Runs API) only exist from Jan 2024; 2023 would only have near-real-time "historical forecasts" with unrealistically small errors. Proposal: simulate 2024, validate PV against PVGIS on 2023** |
| D-008 | Shared energy split: each hour, community grid import shared in proportion to each home's load; exports credited by ownership share (25 % each) | Simple, transparent default. Week 8 replaces this with the fairness rule | — | Assumption |
| D-009 | Brain A = self-consumption rule: PV → homes → battery → grid; never charges from or discharges to the grid | Standard baseline in literature; matches HOMER's default dispatch closely enough for cross-checking | — | Fixed |
| D-010 | Energy balance checked every hour (AC bus and battery internal); tolerance 1e-6 kWh; run stops on violation | Catches bugs immediately | — | Fixed |
| D-011 | NASA POWER timestamps assumed to mark the hour start; `prepare_data.py` checks this by comparing the daily GHI centre with solar noon | NASA POWER convention not stated clearly in the API response | — | Verify when real data is downloaded |
